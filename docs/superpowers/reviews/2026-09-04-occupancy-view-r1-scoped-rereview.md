## Checked and clean

1. **Hover-trace alignment (`figures/occupancy.py:160-178`).** `t_out` returned by `_occupancy_series` is `t_all[full]` where `full = t_all >= t_all[0] + window - 1e-9` — since `t_all` is confirmed strictly increasing with no duplicates on the real dataset (`np.diff(t_all) > 0` holds for all 5893 daily entries; min/max gap both ≈0.00274 yr = 1 day), `full` is a threshold mask on a monotonic array and `t_out` is therefore exactly the contiguous suffix `t_all[m:]`. `t_disp = t_all[disp]` is likewise a contiguous slice `t_all[i0:i1]` of the same underlying array. Because both are literal index-slices of the same float64 array (no recomputation), any element present in both is bit-identical, so `np.searchsorted(t_out, t_disp[k])` followed by `abs(t_out[j]-t_disp[k]) < 1e-9` either matches exactly (full window available — `above[j]`/`below[j]` are index-aligned with `t_out[j]` by construction, since `_occupancy_series` applies the same `full` boolean mask to `t`, `above`, and `below` together) or correctly falls through to "window not yet full" for `t_disp[k] < t_out[0]`. Traced the boundary case explicitly: the first day for which `full` becomes true is, by construction, present in both `t_out` and (when `t_lo` is early enough) `t_disp` at the same value, so there is no off-by-one at the join. `j` can only reach `t_out.shape[0]` (guarded, falls to "not yet full") when `t_out` is empty (window ≥ history span) — never for in-range display days on real data, since `t_out[-1] == t_all[-1] >= max(t_disp)`. Confirmed with a live run against `conftest.M`: `test_strip_hover_trace_covers_every_displayed_day`-style count (5893 days for the default range) matches the independently computed `n_days`, and the two Playwright-verified hover strings (Jun 04 2015, Aug 14 2019) are consistent with this indexing (already machine-verified per the task brief, not repeated here).
