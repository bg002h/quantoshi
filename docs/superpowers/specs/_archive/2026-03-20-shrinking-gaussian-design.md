# Asymmetric Shrinking Gaussian Bands — Design Spec

## Summary

Replace both BubbleModel's QR-based bands and EmpiricalFloorModel's constant-σ
Gaussian bands with asymmetric shrinking Gaussian bands around each model's
bubble composite median. This fixes internal consistency (Q1% can never exceed
Q50%) and captures Bitcoin's volatility compression (floor hardening faster than
ceiling softening).

## Problem

**BubbleModel (current):** Uses independent QR fits per quantile. Each quantile
has its own slope. At low quantiles (Q1%), the slope (5.45) exceeds the
composite's converged support slope (5.13), so Q1% eventually predicts higher
prices than the composite median — logically impossible.

**EmpiricalFloorModel (current):** Uses constant-σ Gaussian bands. Doesn't
capture volatility compression — bands stay the same width forever, when
empirically they narrow over time.

## Solution

Both models use their bubble composite as the median, with quantile bands
generated by:

```
price_at(q, t):
    z = norm.ppf(q)
    if q >= 0.5:
        σ = σ₀_up × t^(-α_up)
    else:
        σ = σ₀_down × t^(-α_down)
    return 10^(log10(composite(t)) + z × σ)
```

Four parameters per model, fitted from windowed residuals (20 log-time bins,
split above/below composite):

| Parameter | BM value | EF value | Meaning |
|-----------|----------|----------|---------|
| σ₀_up | 0.085 | 0.093 | Upside volatility at t=1 |
| α_up | 0.132 | 0.297 | Upside compression rate |
| σ₀_down | 0.075 | 0.085 | Downside volatility at t=1 |
| α_down | 0.218 | 0.295 | Downside compression rate |

BM shows strong asymmetry (α_down/α_up = 1.65 — floor hardens faster).
EF shows near-symmetry (α_down ≈ α_up — composite already models convergence).

## Visual impact

**Before:** Bubble chart quantile lines are straight lines in log-log (from QR).
**After:** Quantile bands follow the composite's bubble humps, narrowing over
time. This is a significant visual change — the bands are wavy, not straight.

## Architecture

### New base class: `_CompositeModel`

Shared base for BubbleModel and EmpiricalFloorModel. Provides `price_at`,
`interp_price`, `find_percentile` using composite interpolation + asymmetric
shrinking σ. Subclasses provide the composite curve and σ parameters.

### BubbleModel changes

- No longer extends `_FitsBasedModel`
- Extends `_CompositeModel` instead
- `__init__` loads composite from `ModelData.bm_comp_by_n` + σ params from pkl
- QR fits remain in pkl for PowerLawModel and other consumers — just not used
  by BubbleModel's `price_at` anymore

### EmpiricalFloorModel changes

- Extends `_CompositeModel` instead of standalone
- Replaces constant σ with shrinking asymmetric σ(t)
- σ parameters come from `model_data_ef.pkl`

### pkl changes

**model_data.pkl** — add 4 fields:
- `bm_sigma0_up`, `bm_alpha_up`, `bm_sigma0_down`, `bm_alpha_down`

**model_data_ef.pkl** — replace `sigma` with 4 fields:
- `sigma0_up`, `alpha_up`, `sigma0_down`, `alpha_down`

### σ fitting tool

`tools/fit_sigma.py` — standalone script that:
1. Loads a pkl (BM or EF)
2. Computes residuals (log10(price) - log10(composite)) at data points
3. Splits into above/below composite
4. Fits σ₀ and α in 20 log-time bins using curve_fit
5. Writes σ parameters back to the pkl

### What stays the same

- PowerLawModel, LPPLModel, ExponentialModel, S2FModel — unchanged
- `_FitsBasedModel` base class — still used by PowerLawModel
- QR fits in pkl — still generated by notebook, still used by PL
- `_app_ctx._ALL_QS` — still comes from `M.QR_QUANTILES`
- Snapshot encoding — model keys unchanged, quantile lists unchanged

## Out of scope

- Changing other model classes (PL, LPPL, Exp, S2F)
- Modifying notebook QR fitting (cell 1)
- MC overlay changes
